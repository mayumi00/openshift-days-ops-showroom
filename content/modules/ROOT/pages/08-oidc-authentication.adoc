= Keycloak による OpenID Connect (OIDC) 認証
:page-toclevels: 1

== モジュールの概要（Module Overview）

**所要時間:** 15〜20 分 +
**形式:** ハンズオンでの OIDC アイデンティティプロバイダー設定 +
**対象者:** プラットフォームエンジニア、運用チーム、セキュリティ管理者

include::partial$console-access.adoc[]

OpenShift は、LDAP、OIDC、HTPasswd、GitHub など、複数のアイデンティティプロバイダーをサポートしています。このモジュールでは、**Red Hat build of Keycloak (RHBK)** をデプロイし、エンタープライズ SSO への現代的なアプローチである OpenShift 用の OpenID Connect (OIDC) アイデンティティプロバイダーとして設定します。

行う作業：

* Keycloak をゼロからデプロイおよび設定する
* 管理コンソールでレルム（Realm）、ユーザー、グループ、および OIDC クライアントを作成する
* OpenShift OAuth と Keycloak を統合する
* OIDC グループが自動的に同期される仕組みを確認する（`oc adm groups sync` は不要）

同じ概念が Microsoft Entra ID、Okta、Google Workspace、および任意の OIDC プロバイダーに適用されます。Keycloak を使用することで統合の双方の側面を確認できます。

== Keycloak のデプロイ（Deploy Keycloak）

=== ステップ 1: RHBK オペレーターのインストール（Step 1: Install the RHBK Operator）

[source,bash,role="execute"]
----
bash <(curl -sL https://raw.githubusercontent.com/rhpds/openshift-days-ops-showroom/main/support/08-oidc-authentication/install-rhbk-operator.sh)
----

NOTE: オペレーターのインストールと CRD の登録が行われるため、1〜2 分かかります。完了するまでお待ちください。5 分以上実行されている場合のみ **Ctrl+C** を押してください。

=== ステップ 2: Keycloak のデプロイ（Step 2: Deploy Keycloak）

Keycloak インスタンスをデプロイします。組み込みデータベースには `dev-file` を使用します（本番環境では外部の PostgreSQL を使用します）。

[source,bash,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: k8s.keycloak.org/v2alpha1
kind: Keycloak
metadata:
  name: keycloak
  namespace: rhbk
spec:
  instances: 1
  db:
    vendor: dev-file
  http:
    httpEnabled: true
  hostname:
    strict: false
  proxy:
    headers: xforwarded
EOF
----

Pod が起動するまで待ちます（これには 1〜2 分かかります）：

[source,bash,role="execute"]
----
echo "Waiting for Keycloak pod to be created..."
ELAPSED=0
until oc get pod keycloak-0 -n rhbk 2>/dev/null; do
  sleep 5; ELAPSED=$((ELAPSED+5))
  [ $ELAPSED -ge 180 ] && echo "ERROR: Timed out waiting for Keycloak pod" && break
done
echo "Waiting for Keycloak to be ready..."
oc wait --for=condition=Ready pod/keycloak-0 -n rhbk --timeout=120s
echo "Keycloak is running"
----

外部アクセスのための Route を作成します：

[source,bash,role="execute"]
----
oc create route edge keycloak --service=keycloak-service --port=8080 -n rhbk
----

管理者認証情報を取得します。Keycloak コンソールへのログインに必要となります：

[source,bash,role="execute"]
----
echo "Keycloak URL: https://$(oc get route keycloak -n rhbk -o jsonpath='{.spec.host}')"
echo "Username: $(oc get secret keycloak-initial-admin -n rhbk -o jsonpath='{.data.username}' | base64 -d)"
echo "Password: $(oc get secret keycloak-initial-admin -n rhbk -o jsonpath='{.data.password}' | base64 -d)"
----

URL をコピーして**新しいブラウザタブ**で開きます。上記の管理者認証情報でログインします。

これで Red Hat build of Keycloak 管理コンソールに入りました。**master レルム**のウェルカムページが表示されます：

image::oidc-rhbk-welcome.png[RHBK admin console welcome page showing master realm, link=self, window=blank]
ここでは、レルム、ユーザー、クライアント、および認証フローを管理します。

== ユーザーとグループの設定（Configure Users & Groups）

=== ステップ 3: OpenShift レルムの作成（Step 3: Create an OpenShift Realm）

Keycloak は**レルム**を使用して、ユーザー、認証情報、およびクライアントのセットを分離します。デフォルトの `master` レルムは Keycloak の管理専用です。アプリケーション用には常に個別のレルムを作成する必要があります。

1. 左側のサイドバーで **Manage realms** をクリックします
2. **Create realm** をクリックします
3. **Realm name** を `OpenShift` に設定します
+
image::oidc-rhbk-create-realm.png[Create realm dialog with OpenShift as realm name, link=self, window=blank]
+
4. **Create** をクリックします

両方のレルムがリストされ、**OpenShift** が現在のレルムとして表示されます：

image::oidc-rhbk-realm-created.png[Manage realms showing master and OpenShift realms, link=self, window=blank]
これで OpenShift レルム内で作業を進めることになります。ここから作成するすべてのもの（ユーザー、グループ、クライアント）はこのレルムに属します。

=== ステップ 4: 最初のユーザーの作成（Step 4: Create Your First User）

Keycloak のユーザー管理インターフェースを理解するために、ユーザーを手動で作成します。

IMPORTANT: 4つのフィールド（**Username**、**Email**、**First name**、**Last name**）すべてに入力する必要があります。Keycloak のユーザープロファイルポリシーでこれらが必須とされており、欠けているものがあると不親切なエラーでログインが失敗します。

**admin1 の作成：**

1. 左側のサイドバーで **Users** をクリックします
2. **Add user** をクリックします
3. ユーザーの詳細を入力します：
   - **Username**: `admin1`
   - **Email**: `admin1@example.com`
   - **First name**: `Admin`
   - **Last name**: `User`
+
image::oidc-rhbk-create-user.png[Create user form with admin1 details filled in, link=self, window=blank]
+
4. **Create** をクリックします
5. **Credentials** タブをクリックします。「No credentials」と表示されます：
+
image::oidc-rhbk-credentials-tab.png[Credentials tab showing No credentials with Set password button, link=self, window=blank]
+
6. **Set password** をクリックします
7. 両方のフィールドにパスワード `OpenShift123!` を入力します
8. **Temporary** を **Off** に切り替えます（ユーザーが初回ログイン時にパスワード変更を強制されないようにするため）
+
image::oidc-rhbk-set-password.png[Set password dialog with Temporary set to Off, link=self, window=blank]
+
9. **Save** をクリックして確認します

=== ステップ 5: 最初のグループの作成（Step 5: Create Your First Group）

Keycloak 内のグループは OpenShift グループにマッピングされます。ユーザーが OpenShift にログインすると、Keycloak のグループメンバーシップが ID トークンに含まれ、OpenShift がそれを読み取ってグループを自動的に作成します。

1. 左側のサイドバーで **Groups** をクリックします
2. **Create group** をクリックします
3. 名前を `ocp-admins` に設定し、**Create** をクリックします

image::oidc-rhbk-groups-created.png[Groups page showing ocp-admins group, link=self, window=blank]
**admin1 をグループに割り当てる：**

1. **Users** をクリック → **admin1** をクリックします
2. **Groups** タブをクリックします。「No groups」と表示されます：
+
image::oidc-rhbk-user-join-group.png[User Groups tab showing Join Group button, link=self, window=blank]
+
3. **Join Group** をクリック → **ocp-admins** を選択 → **Join** をクリックします

=== ステップ 6: 残りのユーザーとグループのスクリプト処理（Step 6: Script the Remaining Users and Groups）

Keycloak UI でユーザーとグループがどのように動作するかを確認しました。それらのクリック操作を繰り返す代わりに、Keycloak REST API を使用して残りのユーザー、グループ、および OIDC クライアントを作成します。これは、本番環境でこの作業を自動化する場合に使用するのと同じ API です。

[source,bash,role="execute"]
----
bash <(curl -sL https://raw.githubusercontent.com/rhpds/openshift-days-ops-showroom/main/support/08-oidc-authentication/setup-keycloak-oidc.sh)
----

TIP: 本番環境では、Keycloak のレルムエクスポートまたは Keycloak オペレーターの `KeycloakRealmImport` CR を使用して、このセットアップ全体を宣言的に自動化します。

Keycloak UI でセットアップを確認します。**Users** と **Groups** をクリックして、3 人のユーザーと 3 つのグループがすべて存在することを確認します。**Clients** → **openshift** をクリックしてクライアント設定を確認します。

== OpenShift への接続（Connect to OpenShift）

=== ステップ 7: OpenShift OAuth の設定（Step 7: Configure OpenShift OAuth）

Keycloak セットアップスクリプトにより、正しいクライアントシークレットを持つ `rhbk-client-secret` が `openshift-config` 内にすでに作成されています。次に、これを使用するように OAuth を設定します：

[source,bash,role="execute"]
----
bash <(curl -sL https://raw.githubusercontent.com/rhpds/openshift-days-ops-showroom/main/support/08-oidc-authentication/configure-oauth-oidc.sh)
----

重要な行は `claims.groups: [groups]` です。これは OpenShift に対し、ID トークンから `groups` クレームを読み取り、そこから OpenShift グループを作成するように指示します。これが、スクリプトがグループマッパーを OIDC クライアントに追加した理由です。

OAuth の展開を待ちます：

[source,bash,role="execute"]
----
oc rollout status deployment/oauth-openshift -n openshift-authentication --timeout=120s
echo "Waiting for all OAuth pods to be ready with new config..."
ELAPSED=0
until [ "$(oc get pods -n openshift-authentication -l app=oauth-openshift --no-headers 2>/dev/null | grep -c Running)" -ge 3 ] && \
      [ "$(oc get pods -n openshift-authentication -l app=oauth-openshift --no-headers 2>/dev/null | grep -vc Running)" -eq 0 ]; do
  sleep 5; ELAPSED=$((ELAPSED+5))
  [ $ELAPSED -ge 180 ] && echo "ERROR: Timed out - check 'oc get pods -n openshift-authentication'" && break
done
echo "OAuth is live with rhbk provider - you can log in now"
----

NOTE: OAuth Pod が新しい設定で再起動するため、1〜2 分かかります。完了するまでお待ちください。5 分以上実行されている場合のみ **Ctrl+C** を押してください。

=== ステップ 8: OIDC ログインと自動グループ同期のテスト（Step 8: Test OIDC Login and Automatic Group Sync）

1. **OCP Console** タブで、ユーザー名（右上）をクリックし、**Log out** を選択します
2. OCP Console タブ名の隣にある **再読み込みボタン**（丸い矢印）をクリックします。両方のアイデンティティプロバイダーが表示されます：
+
image::oidc-login-selector.png[OpenShift login page showing htpasswd and rhbk, link=self, window=blank]
+
3. **rhbk** をクリックします
4. `developer1` / `OpenShift123!` としてログインします

[NOTE]
====
**Authentication error** ページが表示される場合があります：

image::oidc-auth-error.png[Authentication error after OIDC login, link=self, window=blank]
OCP Console タブの隣にある **再読み込みボタン**（丸い矢印）をクリックしてページを再読み込みしてください。
====

何が起こったか確認してみましょう。`developer1` がログインした際、その Keycloak グループメンバーシップが ID トークンに含まれていました。OpenShift はトークンを読み取り、グループを自動的に作成します。手動での `oc adm groups sync` は必要ありません。ターミナルに戻ります：

[source,bash,role="execute",subs="attributes"]
----
oc login -u {openshift_cluster_admin_username} -p {openshift_cluster_admin_password} --insecure-skip-tls-verify
----

[source,bash,role="execute"]
----
oc get groups
----

ID トークンから**自動作成された**、`developer1` をメンバーとする `ocp-developers` が表示されるはずです。手動での `oc adm groups sync` を必要とする LDAP とは異なり、OIDC グループは自動的に表示されます。

TIP: コンソールの **User Management > Groups** でも自動作成されたグループを確認できます。OIDC ではグループが自動的に表示されるため、手動同期手順は不要です。

[source,bash,role="execute"]
----
oc get user developer1 -o yaml
----

出力の `identities` セクションを確認します。アイデンティティプロバイダー（`rhbk`）とユーザーの識別子が表示されます。ユーザーは初回ログイン時に自動作成されました。`groups: null` であることに注目してください。グループメンバーシップは User オブジェクトには保存されません。上記で `oc get groups` から確認したように、OIDC トークンから自動作成された Group オブジェクト上に存在します。次に、それらのグループに RBAC ロールを割り当てます。

== RBAC の設定（Configure RBAC）

.ユーザーとグループは、プロジェクト内またはクラスター全体で実行できる操作を定義するロールにバインドされます
image::diagrams/07_08_rbac.png[OpenShift RBAC, align=center, link=self, window=blank]
=== ステップ 9: RBAC の設定と権限の検証（Step 9: Configure RBAC and Verify Permissions）

OIDC グループに権限を付与します：

[source,bash,role="execute"]
----
# admins グループに cluster-admin を付与
oc adm policy add-cluster-role-to-group cluster-admin ocp-admins

# viewers に cluster-reader を付与
oc adm policy add-cluster-role-to-group cluster-reader ocp-viewers

# プロジェクトを作成し、デベロッパーのアクセス権を付与
oc adm new-project app-development --display-name="Application Development"
oc adm new-project app-production --display-name="Application Production"

oc adm policy add-role-to-group edit ocp-developers -n app-development
oc adm policy add-role-to-group view ocp-developers -n app-production
----

NOTE: `Warning: Group 'ocp-admins' not found` または同様の警告が表示される場合がありますが、これは正常です。OIDC グループは、そのグループのユーザーがログインしたときにのみ OpenShift 内に作成されます。これまでは `developer1` のみがログインしているため、`ocp-developers` のみが存在します。ロールバインディングは作成されており、それらのユーザーがログインしたときに有効になります。

ここで確認します。**OCP Console** タブを再読み込みします。developer1 はすでに OIDC 経由でログインしているため、コンソールにアクセス可能なプロジェクトが表示されるはずです。プロジェクトリストに **Application Development** と **Application Production** が表示されます。

developer1 のトークンを使用してターミナルから権限をテストします：

1. OCP Console（developer1 としてログイン中）で、ユーザー名（右上）をクリック → **Copy login command** → **rhbk** をクリック → **Display Token** をクリックします
+
image::oidc-copy-login-command.png[User menu showing Copy login command option, link=self, window=blank]
+
2. `oc login --token=...` コマンドをコピーしてターミナルに貼り付けます

developer1 としてログインしていることを確認します：

[source,bash,role="execute"]
----
oc whoami
----

`developer1` と表示されるはずです。依然として管理者ユーザーが表示される場合は、トークンによるログインが失敗している可能性があります。もう一度コピーして貼り付けてみてください。

[source,bash,role="execute"]
----
oc auth can-i create deployment -n app-development
----

結果: `yes`（ocp-developers からの edit アクセス権）

[source,bash,role="execute"]
----
oc auth can-i create deployment -n app-production
----

结果: `no`（本番環境では view 専用）

これが標準的な RBAC パターンです。ユーザーはグループに属し、グループはプロジェクトに対する RoleBinding（例: app-development への edit アクセス権、app-production への view アクセス権）を取得します。OIDC では、手動同期を必要とする代わりに、ID トークンからグループが自動的に作成されます。

**管理者アクセスの復元：**

[source,bash,role="execute",subs="attributes"]
----
oc login -u {openshift_cluster_admin_username} -p {openshift_cluster_admin_password} --insecure-skip-tls-verify
----

=== まとめ（Summary）

**実施したこと：**

* Red Hat build of Keycloak をゼロからデプロイおよび設定した
* 管理コンソールでレルム、ユーザー、グループ、および OIDC クライアントを作成した
* 自動グループ同期を駆動するグループプロトコルマッパーを設定した
* OpenShift OAuth を OIDC プロバイダーとして Keycloak と統合した
* ID トークンのクレームからグループが自動的に同期されるのを確認した（手動同期は不要）

**OIDC と LDAP の主な違い：**

* **LDAP:** グループには手動での `oc adm groups sync`（または CronJob）が必要
* **OIDC:** トークンクレームからログインごとにグループが自動的に同期される

両方の方法とも有効です。組織のアイデンティティインフラストラクチャに基づいて選択してください。多くの企業では Keycloak をブローカーとして使用し、LDAP/AD バックエンドとフェデレーションすることで、LDAP の既存のユーザーディレクトリを活かしつつ OIDC の自動同期機能を利用しています。
