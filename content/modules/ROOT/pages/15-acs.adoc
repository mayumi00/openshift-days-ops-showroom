== 学習目標

このモジュールを完了すると、以下のことができるようになります。

* セキュアでないアプリケーションをまとめてデプロイする
* コンプライアンスレポートおよびコンプライアンスチェックをセットアップする
* Red Hat Advanced Cluster Security (RHACS) を使用してワークロードをスキャンする

== セキュアでないアプリケーションのデプロイ

クラスターにセキュアでないアプリケーションをいくつかデプロイしてみましょう。これにより、RHACS の機能を実証するのに役立ちます。

.手順
. ターミナルで次のコマンドを実行して、セキュアでないアプリケーションをデプロイします。
+
[source,bash,subs="+macros,+attributes",role=execute]
----
git clone https://github.com/mfosterrox/demo-applications.git
cd ~/demo-applications
oc apply -f k8s-deployment-manifests/-namespaces --recursive
oc apply -f k8s-deployment-manifests/emojivoto --recursive
oc apply -f k8s-deployment-manifests/apache-struts --recursive
oc apply -f k8s-deployment-manifests/dvwa --recursive
oc apply -f k8s-deployment-manifests/log4shell --recursive
oc apply -f skupper-demo/ --recursive
----
+
アプリケーションがデプロイされているのが確認できます（出力は一部省略されています）。
+
----
namespace/emojivoto created
namespace/apache-struts created
namespace/dvwa created
namespace/emojivoto configured
namespace/juice-shop created
namespace/log4shell created
namespace/nodejs-goof-vuln-main created
----

== セキュリティと環境のインサイト

**RHACS の基本を確認しましょう。**

=== *RHACS の基本*
RHACS は、次のような Kubernetes のセキュリティワークフローに不可欠なツールを提供します。

- 脆弱性管理（プラットフォーム、ワークロード、ノード、および仮想マシン）
- ポリシーライフサイクル管理（Policy-as-Code）
- コンプライアンス監査
- リスクプロファイリング
- 脅威の検出と対応

RHACS を使用すると、CNCF がサポートする Kubernetes 環境全体で、Kubernetes クラスターの安全性とコンプライアンスを確実に維持できます。

[[rhacs-compliance-operator-installation-and-compliance-checks]]
== RHACS と Compliance Operator によるコンプライアンスチェック

本番環境のクラスターとアプリケーションは、セキュリティ標準と内部ポリシーを常に満たしている必要があります。RHACS は OpenShift Compliance Operator と連携して、その状態を測定し、コンプライアンスのギャップを特定して、本番環境に到達する前や（時間の経過とともに）コンプライアンスから逸脱する前にそれらを修正するのに役立ちます。

まず、コンプライアンスチェック結果の違いを確認できるように、ローカルクラスターに構成を追加しましょう。
